# Working on Arandu FCM

This is an Arandu package that pushes to phones, Android and iOS, through
Firebase Cloud Messaging. It keeps the devices of a tenant's users (one entity
with an embedded Hesape Model, `Device`), one policy that decides about it, one
service that owns the database handle, a hesape `notifications.Channel` that
fans a notification out to a user's phones, the client that talks to the FCM
HTTP v1 API, and the optional JSON routes a mobile application calls.
It is a Go module somebody `go get`s and registers by hand in their own
`bootstrap/app.go`, which is the whole difference from working in an
application. There is no service provider, no container and no discovery — if a
line of wiring is not written in the installer's repository, it does not happen.

Read `.agents/skills/` before writing code. Each skill is a procedure, and the
one you need is named by the situation you are in.

## The gates

Nothing is finished until all four exit zero.

```sh
export GOWORK=off
gofmt -l $(find . -name '*.go' -not -path '*/testdata/*' -not -name '*.kyse.go')
go build ./...
go vet ./...
go test -race ./...
```

The feature suite runs on a SQLite file by default and, when
`FCM_TEST_DATABASE_URL` names a PostgreSQL server, on a schema of its own per
test on that server, which is how production runs it:

```sh
FCM_TEST_DATABASE_URL='postgres://user@/db?host=/tmp&sslmode=disable' go test -race ./...
```

A change is not finished until the suite passes on both.

`GOWORK=off` is not borrowed from somewhere else, and here it is not a
preference either. This checkout may sit beside a Go workspace that lists the
framework repositories and does not list this one; when it does, every command
above fails before it compiles anything:

```
pattern ./...: directory prefix . does not contain modules listed in go.work
or their selected dependencies
```

With the workspace off, the module resolves the framework version in `go.mod` —
which is what CI compiles against, and what somebody's `go get` will get.

Both filters on `gofmt` are load-bearing in the toolchain even where this
repository has nothing for them to skip: `gofmt` is the only tool in the chain
that ignores build tags, and `testdata/` is where a fixture is allowed to be
invalid on purpose.

`aru doctor` is not one of the gates, and running it here costs a minute and
answers nothing:

```
this is not an Arandu project: no go.mod, main.go and arandu.toml together.
Run it from inside a project, or create one with `aru new`
```

It exits 1. It reads applications, and this is a library.

It does not read this one after it is installed either, and that is why
`tests/Unit/audit_test.go` exists. The doctor walks the application's own tree,
skips `vendor/`, and opens the one `arandu.mod.toml` at its root; it never loads
a dependency. So `tenant-from-request`, `system-grant-without-tenant`,
`permission-not-declared` and `client-outside-clients` never see a line of an
installed package, and whatever this one must prove about itself it proves in
its own suite or nowhere.

## What this repository holds

| | measured with |
| --- | --- |
| 13 Go files, one per role and one generated, all in one package at the root | `grep -l '^package fcm' *.go` |
| 4 optional routes behind RequireAuth | `grep -c 'r.Action' module.go` |
| 5 actions the policy answers about, 4 of them offered to people | `grep -cE '^\t[A-Za-z]+ +security.Action = ' policy.go` |
| 1 migration, reversible, owning the `fcm_devices` table | `grep -c 'GetName() string' module.go` |
| 3 direct dependencies under `arandu-io` (framework, hesape, and the SQLite connector the tests run on) | `go list -m -f '{{if and (not .Indirect) (not .Main)}}{{.Path}} {{.Version}}{{end}}' all` |

The layout is by role rather than by layer, so the package reads top to bottom:

```
module.go         registration, routes, handlers, jobs, schedule and migrations
config.go         what the application passes in; prints and encodes without its secrets
credentials.go    the Firebase service account, read from the environment, never printed
model.go          the Device entity, its table, its own rules, and what it may answer with
DeviceQuery.go    the query on that table, generated by aru model:build
policy.go         who may do what
service.go        DeviceService: register, unregister, list, and the work done for a push
message.go        Push, the message of the channel, and its validation
channel.go        the hesape notifications.Channel
push.go           delivering a push to a device, directly or as a queue job
client.go         the only file that speaks HTTP: FCM v1 and the OAuth2 exchange
fake.go           a Sender for an application's tests
seal.go           sealing the tokens at rest, and the digest they are found by
audit.go          the events stored in the application's outbox
```

`deviceTable`, in `model.go`, declares the table once: its name, the
`ManualKey` that says the text primary key is written by the application, and
the default `tenant_id` scope. `Devices(db)` is generated from it into
`DeviceQuery.go` and returns the concrete `*DeviceQuery`; that file is never
edited by hand, and `aru model:build --check` says when it is stale. Its
terminals return `*Device` and `DeviceCollection`; keep those pointers
intact, because copying an embedded Model leaves its `Entity` pointer aimed at
the original allocation.

The rules of the entity itself (invariants, derived values, transitions that
change only its own fields) live in the custom block of `model.go`, and they
are pure. The service holds none of them: it validates the request, asks the
policy for a Grant, calls those rules and saves with the Grant. `DeviceResource`
and `DevicesResource` are the deliberate response snapshot boundary, and the
sealed token is not on them.

## What does not exist here

Reaching for one of these is the most common way to write a package that is
rejected in review. None of them is missing by accident.

| A model reaches for | What is here instead |
| --- | --- |
| a service provider, a container, a `Register()` that discovers things | `New(cfg, db, sessions)`, called by hand in the installer's `bootstrap/app.go`. Everything the package touches is a parameter |
| a global `DB`, an `init()` that opens a connection | the `*data.DB` handed to `New`. A package that opened its own connection would be a package the application cannot point at a test database |
| a CRUD Repository beside the Model | `Devices(db)`, reached only by `DeviceService` after `security.Authorize` or a Grant checked for the work |
| a tenant read from the path, the body, the query or a header | `data.Tenant(g)`, from the Grant, which came from the session or from the notification that was authorized |
| a permit-all branch in the policy "for now" | nothing. The policy denies, and an action is opened by writing the rule that opens it |
| an `interface{}` config, a map of options, an env var read at call time | the typed `Config` struct, validated by `New`. The only environment the package reads is what `CredentialsFromEnv` is handed the lookup of, by the application |
| a `panic` on bad wiring | an `error` from `New`. A wiring mistake found at boot costs one restart |
| a third dependency, or Google's SDK for a JWT and one POST | the standard library. This module is imported into other people's builds, and a service account exchange is eighty lines |
| an HTTP call anywhere but `client.go` | `Sender`, the interface the rest of the package reaches Firebase through, with `Client` and `Fake` behind it |
| a retry loop, a goroutine or a sleep around a send | the host queue's worker: a retryable failure is returned and the worker backs off, at least as long as Firebase's Retry-After; a failure that cannot pass is parked once. Without a queue there is no retry at all |
| a token in a log line, an error, `String()` or JSON | `Credentials`, `Config` and `Outgoing` print as `[redacted]` in every form; `Device` has no token in its JSON; `client.go` scrubs the secrets out of any text from the provider before it becomes an error |
| screens | the services and the JSON routes. The application draws its own |

## The properties

These are the reason the package is shaped the way it is. A change that breaks
one of them is not merged, whatever else it improves. `tests/Unit/policy_test.go`
checks the first four against the code.

1. **The policy denies by default**, and has no branch that allows an action
   nobody was given. `TestThePolicyDeniesEveryActionByDefault` walks every
   action with an administrator subject that carries a role and no action, and
   requires `security.ErrForbidden` from each. `DeviceClean` is given to nobody:
   the scheduled clean issues its own Grant, and the policy refuses it to any
   subject.
2. **Every function that reaches the Model decides first.** Every exported
   `DeviceService` method calls `security.Authorize`; the work done for a push
   or the clean calls `Check` on the Grant it was handed, for
   `notifications.ActionSend` or `DeviceClean`, before its first query.
   `TestEveryFunctionAuthorizesBeforeTheModel` reads the source,
   `TestTheServiceRefusesBeforeReachingTheModel` gives the service a nil handle
   so even constructing `Devices` in the wrong order fails.
3. **The tenant comes from `data.Tenant(g)`**, on every path, read and write.
   `TestTheTenantComesFromTheGrant` and
   `TestTheServiceWritesTenantOnlyFromTheGrant` hold both halves, and the feature
   suite proves that a device of another tenant is neither listed, removed nor
   pushed to.
4. **Nothing reaches the Model without passing the first two.** The denial suite
   constructs the service with a nil database, so a call to `Devices(nil)` would
   panic. Every refusal it asserts is therefore proof that authorization
   happened before Model construction.
5. **No secret leaves.** The service account, the application key and the
   registration tokens are in no log line, error, `String()` or JSON. The unit
   suite walks every way a value can be shown; the feature suite makes the
   fake Firebase echo secrets back and reads the errors and the log.
6. **Nothing is sent twice by the module.** The delivery has no loop of its own.
   A 401 repeats the send once with a new access token and never again; every
   other retry is the queue's, bounded by the job's tries.

`policy_test.go` holds the first four by calling the code. `tests/Unit/audit_test.go`
holds the same shape by *reading* it: no function outside `DeviceService` reaches
the Model, every tenant write in the service comes from `data.Tenant(g)`, and no
tenant accessor reads request input.

It also compares `arandu.mod.toml` against what the code *calls* —
`os.ReadFile`, `exec.Command`, `http.Get`, `.Do`, a method named `Migrations` —
rather than against what it imports, because `net/http` is imported by
everything with a route and says nothing. Both directions fail: used and not
declared, which is `permission-not-declared` where the doctor runs it, and
declared and not used, which is a warning there and a failure here because
`go test` has one outcome. Adding an outbound call, a file read or a process
means declaring it in the same commit, and the suite is what says so.

The route namespace is not syntax, so it is held where the routes exist.
`TestTheRoutesAreUnderThePrefixAndOutsideTheFrameworkNamespace`, in
`tests/Feature/routes_test.go`, registers the module and reads the table back:
a prefix arrives through configuration, and `/_arandu/` is refused when the
application boots — in the installer's process, after publication.

What the audit does not reach is written at the top of the file it lives in. It
reads syntax, so dynamic dispatch, reflection, and wrappers around the named
seams are invisible to it. A green run means no such thing was found written
down, not that none exists.

## Writing code

Every copyright notice must use exactly
`Copyright (c) HYZIS - SERVICOS DIGITAIS LTDA - EPP`, without a year or an
abbreviated company name.

Everything in the source is in English: identifiers, doc comments, internal
comments, error messages, log messages, and the names and messages of tests.
`pkg.go.dev` publishes the doc comments and its readers are users of this
package.

Every exported symbol carries a doc comment, and the comment documents the
symbol and nothing else. Why a signature is what it is belongs there when it is
a fact about the code — *"the value is held because Go does not build a type
from a string"* stays. A date, an issue number, a version in progress or the
name of another repository does not.

Tests go under `tests/`, in a capitalized category directory declaring a
lowercase external package: `tests/Unit` holds `package unit_test`,
`tests/Feature` holds `package feature_test`. Both import the package by its
module path, which is what makes them see exactly what a caller sees. A test
that genuinely needs something unexported goes beside the code as
`*_internal_test.go`, and the suffix is how it says so.

Commits are made with the identity of the repository (`HYZIS <admin@hyz.is>`),
signed off, with no attribution of any tool. Work goes to `develop`, and
`main` is moved to it by fast-forward; there is no force-push.
